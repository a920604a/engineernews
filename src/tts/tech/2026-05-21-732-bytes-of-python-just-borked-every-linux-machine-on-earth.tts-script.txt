732 bytes。比一封 email 的簽名檔還小的 Python 腳本，可以在你的 Ubuntu、Debian、RHEL、Arch、SUSE 上直接拿到 root 權限。這是今年四月正式披露的 CVE-2026-31431，研究員幫它取了個名字叫「CopyFail」。

先說清楚這個漏洞在做什麼。Linux 核心裡有個叫 authencesn 的加密模板，負責處理認證加密相關的底層操作。問題出在這裡面有一段加密操作失敗時的處理邏輯——當操作失敗、但頁面內容已經被部分修改時，核心沒有正確地把這個頁面標記成需要丟棄或回寫。

這個疏漏打開了一個四 bytes 的精確寫入窗口，讓一個沒有任何特殊權限的普通使用者，可以對任何可讀檔案的**頁面快取**動手腳。

你可能會問，改頁面快取又怎樣？這裡有個關鍵：Linux 系統裡所有 process 實際上讀取的是記憶體中的頁面快取，不是直接讀磁碟。所以當你竄改了頁面快取裡的 `/usr/bin/passwd`，下次有人執行 passwd 的時候，跑的是你改過的版本——而磁碟上的原始檔案分毫未動。

這就是最讓人頭皮發麻的地方：**磁碟上的檔案通過所有 checksum 驗證，但系統跑的是你改過的版本。** 傳統的完整性監控工具，像 AIDE 或 Tripwire，因為比對的是磁碟上的雜湊值，完全偵測不到這種攻擊。SELinux 和 AppArmor 的防護在這裡也沒有用武之地。日誌裡不會留下明顯痕跡。這是一個天然的無痕提權技術。

CVSS 評分是 7.8，定性為本機提權漏洞，理論上你得先登入系統才能利用。這限制了遠端大規模攻擊。但在容器化環境裡，這個限制的意義就小很多了。

Linux 頁面快取是整個系統共享的——跨所有 process、跨所有容器。Kubernetes 叢集裡，攻擊者只要拿到單一 pod 的程式碼執行能力，透過 CopyFail 就可以汙染同一節點上所有工作負載共用的記憶體，進而提權到 K8s node。那些跑 CI/CD 流水線、或是讓不受信任的程式碼跑在共用節點上的環境，是最需要立即關注的目標。

另一個讓人印象深刻的地方是這個 exploit 的寫法。整個腳本只用了 Python 標準函式庫——os、socket、zlib，需要 Python 3.10 以上。不需要安裝任何第三方套件，不需要編譯 C 程式，幾乎所有現代 Linux 系統預裝的 Python 版本就夠用了。低技術門檻加上廣泛的影響範圍，這個組合很危險。

好消息是修補程式已經在四月一日合併進 Linux 主線核心，各大發行版也陸續透過標準更新通道推出修補版本。處理方式很直接：更新核心，重開機。Ubuntu 和 Debian 用 apt 更新 linux-image-generic；RHEL 和 Fedora 用 dnf update kernel；Arch 就 pacman -Syu linux。更新前可以先用 `uname -r` 確認目前跑的核心版本。

收尾前整理三個重點。第一，如果你管著 Kubernetes 叢集，這是優先等級最高的修補項目，共用節點的多租戶環境尤其緊迫。第二，這個事件點出了現有完整性監控工具的系統性盲點——它們看磁碟，但攻擊發生在記憶體。第三，authencesn 不是唯一做 in-place 加密操作的核心元件，這種假設可能還藏在其他地方。CopyFail 或許不是最後一個。
