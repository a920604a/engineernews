STT-TTS Unified，簡單講，就是一個把「語音合成」跟「語音辨識」兩件事，收進同一個網頁介面的自架平台。它的設計取向很清楚：語音合成，也就是 TTS，直接借用 Microsoft Edge TTS 的免費神經語音；語音辨識，也就是 STT，則用 OpenAI 的 Whisper，完全在你自己的機器、在 CPU 上離線跑。整套系統，不需要顯示卡，也不需要任何 API Key。

那為什麼要這樣設計？一般來說，你要同時做合成跟辨識，常常得東拼西湊好幾個工具；商業 API 又往往綁著用量計費跟金鑰管理，很麻煩。這個專案就是刻意把兩件事收在一起，而且把成本壓到零。TTS 這邊，直接呼叫 Microsoft 的免費服務，提供三百二十二種多語言語音，還會依照你輸入的語言，自動幫你篩掉不能用的語音。STT 這邊，Whisper 是開源模型，完全本地執行，可以離線用。

代價其實分得很乾脆：TTS 因為要打 Microsoft 的服務，所以需要網路；STT 則是純本地、可離線。但兩邊都不需要金鑰。

再來講純 CPU 這件事。這個專案是以「不用顯示卡」為前提去設計的。硬體門檻很低，最低四 GB 記憶體、五 GB 磁碟就能跑；如果你要用 medium 或 large 這種比較大的模型，建議拉到八 GB 以上。Whisper 預設用的是 base 模型，在一般筆電的 CPU 上，一段語音大概十到三十秒就能辨識完。想要更高精度的話，直接在設定檔裡把它換成 small 或 medium 就好，完全不用升級任何硬體。

接下來是我覺得後端最值得一提的地方——它把引擎抽象成「可抽換元件」。做法是用 Protocol 介面，加上工廠函式。它先定義了 STTEngine 跟 TTSEngine 兩個 Protocol，也就是兩份介面約定；然後 WhisperEngine 跟 EdgeTTSEngine 各自去實作對應的介面；最後由一個 engine factory，依照你的設定，回傳實際要用的引擎。這樣的好處是什麼？將來你如果想把 Whisper 換掉，或是不想用 Edge TTS 了，你只要新增一個實作那份 Protocol 的類別就好，呼叫端一行都不用改。

前端這邊是 React 19 加 Vite 加 TypeScript，UI 用的是 Apple 那套語意色彩系統，也支援自動跟隨系統偏好的深色模式。所有合成跟辨識的結果，都會寫進 SQLite，你可以在歷史紀錄裡直接播放跟下載音檔。

然後 STT 的流程，我要特別講一下，因為語音辨識是很耗時的任務，所以它採背景轉換。你上傳音檔之後，Whisper 是在背景跑推論，同時透過 SSE，也就是 Server-Sent Events，把進度即時推回前端；跑完之後，再用瀏覽器通知提醒你。這個設計的意義是，你不用一直盯著畫面等，它也不會卡住你其他的操作。

至於設定跟部署。所有設定都集中在根目錄的 config.yaml，是階層式的結構，STT 引擎跟 TTS 引擎可以分開調。比較實用的一點是，設定可以被環境變數覆蓋，優先順序是：環境變數最高，再來是 .env，最後才是 config.yaml。命名規則是用區塊、子區塊、鍵值，中間用雙底線串起來，比如說你要臨時把 Whisper 模型換成 small，設一個環境變數就搞定，不用去動檔案。部署則是用 Docker Compose 的 multi-stage build，clone 下來、進資料夾、make up，一鍵就啟動，開 localhost 八零零八就能用。本地開發的話，make install 幫你建好 Python 環境跟裝好 npm 相依，make dev 會同時把後端跟前端一起拉起來。

好，總結一下這集的重點。第一，它用一個很務實的組合——免費的 Edge TTS 配上本地的 Whisper——把語音合成跟辨識收進同一個介面，全程免 GPU、免 API Key。第二，後端用 Protocol 加工廠模式把引擎做成可抽換元件，未來要換掉底層模型，呼叫端完全不用動，這是它架構上最漂亮的一手。第三，STT 走背景推論加 SSE 進度回報，避免耗時任務卡住使用者。如果你想自架一套語音工具，又不想付雲端的錢，這會是一個很輕量的起點。
