選錯硬體，在 AI 時代真的很燒錢。

以前這個問題很簡單——大部分工作用 CPU，需要圖形處理就加 GPU。但現在你還要知道 TPU 是什麼、什麼時候用 GPU 反而比 CPU 慢，以及為什麼。

先講最核心的差異。

CPU 的設計哲學是「讓每個核心盡可能快」。它有亂序執行，可以不照程式碼順序、提前執行後面的指令；有分支預測，在 if/else 還沒判斷完之前就先猜一個方向開始跑；還有多層快取，把資料放在離核心最近的地方，避免等待主記憶體——主記憶體比 L1 快取慢大約一百倍。這些機制讓 CPU 在控制流複雜的任務上非常強，比如 Web 伺服器、資料庫查詢、複雜業務邏輯。但核心數通常只有八到六十四個，這是它的天花板。

GPU 的設計哲學完全相反。NVIDIA H100 有將近一萬七千個 CUDA 核心，這些核心都很「笨」，不擅長複雜判斷，但在做矩陣乘法這種規律操作時，同時平行執行的能力讓吞吐量遠超 CPU。這就是為什麼深度學習訓練和大批量推理選 GPU——你的模型在跑前向傳播時，本質上就是一堆矩陣相乘。

但 GPU 有一個常被忽略的誤用場景：單個請求的即時推理。如果你的服務每次只處理一個請求，GPU 可能反而比 CPU 慢，因為資料從 CPU 搬到 GPU 的 overhead，已經超過了計算本身省下的時間。控制流複雜、充滿條件判斷的邏輯也一樣，GPU 的架構在遇到大量分支時效能會急劇下降。

TPU 是 Google 從 2016 年開始自研的 AI 加速器，完全針對神經網路中最常見的操作——矩陣乘法——做極致優化。它的關鍵架構叫「脈動陣列」。傳統 GPU 做矩陣乘法時，每個計算單元要反覆從記憶體讀資料；脈動陣列讓資料直接在計算單元之間流動，資料經過每個單元時順手做計算，大幅降低記憶體頻寬的壓力。Google 用 TPU 訓練了 PaLM、Gemini 這些大模型。限制是什麼？原生不支援 PyTorch，只能在 Google Cloud 上用，控制流複雜或小批量的場景也不適合。

來說說成本，這才是最實際的部分。

以 Google Cloud 為例粗略比較：一台普通 CPU 機器，八核三十二 GB 記憶體，每小時大約四毛美金；T4 GPU 是三毛五到七毛；A100 每小時將近三到四塊；H100 更貴，六到十塊；TPU v4 大約三塊兩毛。數字本身沒那麼重要，重要的是利用率。如果你租了 A100 但 GPU 利用率只有三成，你有七成的錢在燒。第一個要看的指標是 `nvidia-smi` 裡的 `gpu_util` 欄位。

那實際上怎麼選？

線上推理服務、延遲要求高的，batch size 小的場景先考慮 CPU 或 T4，不要一上來就 A100。訓練大模型，PyTorch 用 H100 叢集，JAX 或 TensorFlow 的工作負載在 Google Cloud 上 TPU 是最優解。本機開發的話，Apple Silicon 的統一記憶體架構讓 CPU 和 GPU 共享記憶體，對中等大小的模型有出乎意料的優勢；消費級的 RTX 4090 在 VRAM 夠用的情況下，訓練效率也接近 A100，但價格只有幾分之一。

收尾說三個核心要點。

第一，硬體選擇取決於工作負載的計算模式，不是「跑 AI 就用 GPU」這麼簡單。第二，GPU 的常見誤用是小 batch 即時推理，這種場景 CPU 往往更划算。第三，成本的關鍵不是單價，是利用率——先把現有硬體跑滿，再考慮升級。
