Python 有一個函數叫 `reduce`，它活在一個有點尷尬的位置——存在、有人用，但 Python 的創始人 Guido van Rossum 卻公開說他「幾乎不用它」，甚至在 Python 3 的時候把它從內建函數降格，移到 `functools` 模組裡。光是這個故事，就值得我們認真聊一聊。

`reduce` 的核心概念其實很簡單：拿一個二元函數，反覆套用在一個序列上，把整個序列「折疊」成一個值。舉個例子，你有一串數字 1 到 5，用 `reduce` 搭配加法，它的運算過程是：先把 1 和 2 加起來得到 3，再把 3 和 3 加起來得到 6，然後是 6 加 4 得 10，最後 10 加 5 得 15。就像把一疊牌一張一張合併成一張。

你也可以給它一個初始值，這個初始值會當成第一個「累積結果」，在序列開始之前就先放進去。空序列的時候它也不會爆掉——這個設計其實很貼心。

那 `reduce` 真正有用的地方在哪？有幾個場景值得記起來。

第一個是巢狀字典取值。假設你的資料結構是一層包一層的字典，你有一個 key 的路徑列表，用 `reduce` 可以一行就鑽進去取值，比遞迴寫法簡潔很多。

第二個是合併多個字典。你有一個列表，裡面放了好幾個字典，用 `reduce` 可以把它們全部合併成一個，這個用法在處理配置合併的場景蠻常見的。

第三個，也是最「函數式」的用法：函數組合。如果你想把多個函數串成一個 pipeline，讓資料依序流過每個函數，`reduce` 可以很優雅地實現這個 compose 模式。

不過這裡要澄清一個常見的誤解：`reduce` **不比 for 迴圈快**。在 CPython 裡，`reduce` 本身有函數呼叫的額外開銷，實際上通常比直接寫 for 迴圈還慢一點。所以如果你選擇用 `reduce`，出發點應該是「表達方式」，而不是效能。

`reduce` 代表的是一種聲明式的思維——你在描述「這個操作的結構是什麼」，而不是「怎麼一步一步去做」。這在函數式編程背景下很自然，但 Python 的哲學不是這樣的。

Guido 說得很直白：除了加法和乘法，每次看到 `reduce`，他都要花一點時間才能想清楚它在幹嘛。這是很誠實的自我反省，也說明了 `reduce` 的問題——它讓簡單的事情看起來複雜，讓複雜的事情看起來神奇，但神奇不等於清楚。

所以判斷要不要用 `reduce`，有個簡單的方法：如果你需要超過三秒去想它在做什麼，就換成 for 迴圈。

具體來說，累加用 `sum`，累乘用 `math.prod`，找最大值用 `max`——這些內建函數都比 `reduce` 更直觀。需要建構列表就用 list comprehension。`reduce` 真正有位置的，是那些沒有對應內建函數的累積操作，特別是動態函數組合、或是處理任意深度巢狀結構的時候。

總結三件事：第一，`reduce` 是「折疊」操作，把序列累積成單一值，概念本身不難；第二，它不帶來效能優勢，帶來的是聲明式風格，而這在 Python 裡不一定是加分；第三，有內建函數就用內建函數，可讀性是 Python 最核心的價值——這個原則比任何花俏的寫法都重要。
