影片製作這件事，一直是個隱性門檻很高的工作。你得會剪輯、得找素材、得錄旁白，光一支三分鐘的說明影片，半天就沒了。但現在這個流程可以被根本性地打破——不是靠某個單一的 AI 工具，而是靠一條 Agent 流水線。

今天要聊的，就是怎麼用 n8n 把 LLM、TTS、還有影片生成 API 串在一起，讓你只需要丟一個主題進去，幾分鐘後就能拿到一支帶旁白的完整影片。而且全程不用寫一行程式。

先講整體架構。這套系統的核心概念是工具鏈——每個步驟的輸出，就是下一步的輸入。流程大概是這樣：你輸入主題，LLM 先生成腳本；腳本同時走兩條路，一條去 TTS 轉成旁白音頻，另一條讓 LLM 產出視覺描述，再丟給影片生成 API 去生成畫面；最後 FFmpeg 把音頻跟影片合併起來，輸出你要的 MP4。

這不是單一 AI 模型在做所有事，而是多個工具分工協調——這才是「Agent」這個詞真正的意思：讓 LLM 決定要呼叫哪些工具、以什麼順序跑。

講講工具選擇。腳本生成的話，Claude 3.5 Sonnet 或 GPT-4o 都行，關鍵是要讓它輸出 JSON 格式，這樣下游處理才方便。語音合成方面，ElevenLabs 音質最自然，有免費額度可以先試；Azure AI Speech 繁體中文支援不錯，企業用比較穩；如果只是開發測試，Edge TTS 免費、音質夠用。影片素材生成，Runway Gen-3 品質高，Pika 操作簡單，如果需要 AI 虛擬人物主播，HeyGen 是個選項。串接平台用 n8n，開源、可以自架，透過 HTTP Request 節點就能接任意 API——這是整套方案能不用寫程式的關鍵。

在 n8n 裡面，整個流程大概八個節點。Webhook 接收主題輸入、HTTP Request 打 Claude API 拿腳本、Code 節點解析 JSON 拆分段落、逐段打 ElevenLabs 生成音頻、逐段打 Runway 生成影片片段、最後 Execute Command 呼叫 FFmpeg 合併。設定完一次，之後每次觸發 Webhook 就全自動跑。

有一個地方是整套系統最關鍵的，就是給 LLM 的 Prompt 設計。你必須要求它輸出嚴格的 JSON 結構：標題加上分段陣列，每段包含旁白文字和畫面描述。特別注意，畫面描述要用英文寫，因為 Runway、Pika 這些影片生成工具對英文的理解明顯比中文好。

跟傳統流程比起來，差距是很直觀的。寫腳本，以前要三十到六十分鐘，LLM 三十秒搞定；配音，以前要錄音室或外包，現在 TTS 即時生成；素材，以前買素材庫或自己拍，現在直接生成；剪輯，以前要手動操作剪輯軟體，現在 FFmpeg 自動合併。總時間從半天到數天，壓縮到五到十五分鐘。

但這套方案也不是萬能的，幾個真實限制要說清楚。首先是費用，Runway 按秒計費，長影片成本會很可觀。其次是生成時間，每段影片通常要等一到三分鐘，整條流水線跑完可能要二十分鐘。第三是畫面一致性，不同段落 AI 生成的畫風可能不統一，要在 prompt 裡面強調風格一致性。最後，如果是版權敏感的商業廣告，AI 生成素材的授權問題目前還不明確，要小心。

適合用這套方案的場景，是大量重複性內容，比如產品介紹、教學影片、新聞摘要；需要多語言版本的，TTS 換個語言參數就好；還有快速驗證創意的情境。不適合的是需要真人情感連結的內容，或者對畫面品質有高精度要求的場合。

最後收斂三個核心點：第一，這套 Agent 的本質是工具鏈協調，不是單一模型；第二，n8n 加 HTTP Request 節點讓整件事真的不需要寫程式；第三，Prompt 的 JSON 格式設計是整套系統能不能跑順的關鍵，值得花時間打磨。
