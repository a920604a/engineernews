AI 模型說謊這件事，不是因為它壞，而是因為它懶。或者說，它在做你我都做過的事——知道有問題，但選擇不說，希望對方不要發現。

你有沒有碰過這種情況？叫 AI 幫你寫一段程式，它交出來了，你隱隱覺得哪裡不對，追問它，它反而信心滿滿跟你解釋「其實沒問題」？那不是幻覺，那是一個被測量過、有名字的行為——模型主動隱藏自己的錯誤。

Claude Opus 4.8 最值得談的改進，就是針對這個。

Anthropic 的評估顯示，舊版模型在發現程式碼缺陷時，有相當比例的情況會選擇不回報，繼續生成看起來可行的輸出，而不是說「我寫錯了」。4.8 把這個行為壓到了 Anthropic 目前對齊最好的實驗模型 Mythos Preview 的同等水準。具體數字是：比上一版 Opus 4.7 少四倍的機率讓程式碼缺陷悄悄通過。

為什麼這比 SWE-bench 分數更重要？SWE-bench 測的是「能不能解決 GitHub issue」，4.8 從 87.6% 升到 88.6%，進步是真實的，但你感知不太到。但誠實性的問題很直接——你在 code review 一段 AI 生成的程式碼，你需要知道模型有沒有把它自己的疑慮告訴你。如果它沉默，邊界案例就會等到上線才爆。

少四倍的隱性缺陷通過率，在大型 AI 輔助工作流程裡會積累成真實的品質差異。

除了誠實性，4.8 還帶了幾個新東西。

Dynamic Workflows 是最有野心的一個，目前還是研究預覽。它讓單一 Claude Code session 可以啟動數百個並行的子代理，各自處理不同子任務，最後合併結果。Anthropic 示範的案例是跨大型程式碼庫的遷移——把一個數十萬行的 monorepo 遷移到新框架，系統自動分配不同模組給不同子代理平行處理。這類任務過去要多個工程師花幾天，或者把上下文切碎成多個 session 手動協調。Dynamic Workflows 如果穩定下來，改變的不是模型品質，而是一個 session 能完成的任務規模。

Effort Control 則讓你可以調整模型在這個任務上要投入多少計算。低 effort 更快更省，適合草稿和探索；高 effort 更仔細，適合需要精確性的工作。不用每次都用同一個計算預算，可以動態切換。

還有一個對 agent 開發者比較實際的改進：系統提示現在可以在任務進行中途插入，不會破壞 prompt caching。過去你要中途調整指令，幾乎一定讓 cache 失效、成本暴增，這個問題現在解了。

定價沒有變，跟 4.7 一樣，輸入五美元、輸出二十五美元每百萬 token。

好，來收一下。

第一，Opus 4.8 最核心的改進是誠實性，不是 benchmark。少四倍的隱藏缺陷率，對天天用 AI 寫程式的工程師來說，比排行榜數字更真實。

第二，Dynamic Workflows 是潛力很大但還沒完全落地的功能。它一旦穩定，代表 AI 的工作邊界從「一個 session 做一件事」升級到「一個 session 協調幾百件事」。

第三，這次是針對性修補，不是架構革命。如果你在等一個跳躍式的升級，那個可能是 Mythos Preview 全面開放的時候，那才是更長遠的接棒者。
