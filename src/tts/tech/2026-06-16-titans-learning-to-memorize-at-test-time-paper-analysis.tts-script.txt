序列模型有一個還沒被真正解決的老問題：你要嘛要強大的記憶，要嘛要線性的計算複雜度，但你很難兩個都要。Transformer 注意力機制很強，但計算量是序列長度的平方，一旦上下文拉長，成本就爆炸。Mamba 這類 State Space Model 效率很高，但它的記憶容量是固定的，壓縮上限就在那裡。Google DeepMind 的 Titans 論文想打破這個僵局，而它的切入點很不一樣。

傳統深度學習有個預設：訓練和推論是分開的。所有「知識」在訓練結束後就被凍進模型權重裡，推論時不再更新。這在短上下文沒問題，但如果你要分析一份幾萬字的技術文件、做跨章節的推理，模型很容易把早期的關鍵資訊忘掉。Titans 的核心主張就是：記憶應該在推論時持續更新。就像你在讀一篇很長的文章，你會隨時把重要的東西記進工作記憶，而不是只靠你在學校學到的東西去猜。

那具體怎麼做？Titans 引入了一個叫做神經長期記憶模組的東西。這個記憶模組本身是一個小型的神經網路，它的參數就是記憶的載體。當新的 token 進來，它會計算這個 token 對記憶模組的預測誤差，然後用梯度下降去更新記憶模組的參數——這個過程發生在推論期間，不是訓練期間。讀取記憶的方式也很直覺：你拿一個 query 去做前向傳播，記憶模組就吐回你想要的資訊。

這裡有個設計得很精巧的地方，叫做「驚訝度」。不是每個 token 都值得記住，對吧？重複的、可預測的資訊沒必要一直更新。Titans 用梯度的大小來衡量一個 token 有多「出乎意料」——預測誤差越大，梯度越大，就給這個 token 更強的記憶更新力道。這讓記憶系統自動聚焦在新穎或重要的資訊上，非常符合人類記憶的直覺。

記憶模組還有一個遺忘機制。如果不斷累積，舊的記憶會干擾新的。所以每次更新時，舊的參數值會按比例衰減，像是指數遞減一樣，讓模型優先保留近期資訊，自然地釋放掉不再重要的東西。另外也加了動量，跟 SGD 的動量概念一樣，防止因為某個奇異的 token 讓記憶劇烈震盪。

論文提出三種把這個記憶模組整合進 Transformer 的方式。第一種叫 MAC，記憶作為上下文：把記憶模組的輸出直接拼到輸入 token 旁邊，一起送進注意力層，最直觀。第二種叫 MAG，記憶作為閘控：記憶模組的輸出不是直接拼接，而是去控制注意力輸出的比例，更靈活。第三種叫 MAL，記憶作為獨立層：記憶模組和注意力層交替堆疊，模組化最高、最容易替換。實驗結果是 MAG 在大多數 benchmark 上最好，但 MAC 在需要精確定位記憶的任務上更穩定。

跟其他方案比，Titans 最大的差異化就是「推論時持續學習」這件事。Transformer 做不到、Mamba 做不到、RAG 靠的是外部資料庫檢索也不算。這是 Titans 獨有的。在長上下文 benchmark 上，Titans-MAG 在多個子任務超越了 GPT-4 Turbo；在 Needle-in-a-Haystack 測試裡，也就是在幾十萬 token 的文件裡精確找到一個資訊，Titans 的成功率顯著高於 Mamba。

當然有實際的取捨要面對。每個 token 都要跑一次反向傳播來更新記憶，這在生產環境是有延遲成本的，不能忽視。記憶模組的大小決定記憶容量上限，不同任務要調，增加了超參數複雜度。遺忘速率的設定對不同任務很敏感，目前還沒有自適應方案。訓練穩定性也比純 Transformer 差一點，主模型跟記憶模組的互動動態讓訓練曲線比較不規律。

整理一下三個核心帶走點。第一，Titans 真正有趣的地方不是架構本身，而是「推論時學習」這個設計思想的具現化——它讓模型在服務請求的當下仍然可以更新自己的記憶。第二，驚訝度這個機制非常優雅，它讓記憶自動聚焦在真正重要的資訊，而不是暴力地記住所有東西。第三，這個方向跟 Test-Time Compute 的大趨勢是一脈相承的，只是 Titans 選擇聚焦在記憶，而不是推理鏈。長上下文的問題還沒有完美答案，但 Titans 至少給了一個很有說服力的方向。
