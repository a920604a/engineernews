You know that folder of GitHub stars you've been meaning to revisit? The one full of "I'll use this someday" repos? These aren't those. Every tool on this list solves exactly one problem — and most of them, you'll find yourself reaching for within three days of discovering them.

Let's go through ten of them.

**Carbon** is first, and it's deceptively simple. You need to share a code snippet — on a blog, in a slide deck, on social media. A raw screenshot looks terrible. Carbon lets you pick a theme, a font, a background gradient, and export a clean PNG or SVG that actually looks designed. That's it. One thing, done beautifully. The caveat: it's an image, so nobody can copy the code from it. Use it for visual communication, not for documentation people need to interact with.

**Excalidraw** sits in a similar "one job" category. You've probably used Lucidchart or Draw.io at some point. They work, but everything they produce looks like a corporate flowchart from 2015. Excalidraw makes deliberately hand-drawn style diagrams — that slightly rough, whiteboard aesthetic that signals "this is a sketch, not a finished spec." It's fully open-source, you can self-host it, it does real-time collaboration, and there's a VS Code extension so you can open diagram files right in your editor.

**nektos/act** might be the highest-leverage tool on this list for anyone who uses GitHub Actions. The problem it solves: you tweak a workflow file, push it to trigger CI, wait for it to run, find out it failed, push a fix, wait again. It's an absolute time sink. Act lets you run GitHub Actions workflows locally using Docker. You run a single command targeting your push event or a specific job, and you get the same execution environment as GitHub's servers — right on your machine. Iteration goes from minutes per cycle to seconds. One gotcha: some GitHub-specific actions need extra configuration to behave correctly outside the real GitHub environment, so it's not perfect parity, but it's dramatically better than push-and-pray debugging.

**Hoppscotch** is what you reach for when Postman starts feeling like it's working against you. Postman's free tier has gotten increasingly restrictive, and by default it syncs your API collections to their cloud. Hoppscotch is fully open-source, supports REST, GraphQL, and WebSocket testing, and can be self-hosted so your data never leaves your infrastructure. If you've been tolerating Postman out of inertia, this is worth a look.

**Bun Shell** is a feature buried inside Bun, the JavaScript runtime, and it deserves more attention on its own terms. The classic problem: you want to run some shell commands from a JavaScript or TypeScript script. The native way to do it — child process execution — is verbose and annoying. Third-party shell libraries work but feel dated. Bun's shell API lets you write actual shell syntax directly inside your JavaScript, with full TypeScript types, cross-platform support including Windows, and async-friendly output. It's the modern answer for build scripts and automation in Node or Bun projects.

**Ink** is one of those tools that makes you wonder why you ever did things the hard way. If you've ever needed to build an interactive CLI — something with a progress bar, dynamic output, user prompts — you either dealt with raw terminal escape codes or reached for a library with a learning curve. Ink gives you React. Actual React components, with flexbox layout and color and text styling, rendering to the terminal. Gatsby's CLI and Parcel's CLI are both built with it. If you already know React, the mental model transfers completely.

**Slidev** is for engineers who need to give talks but hate PowerPoint. You write your slides in Markdown. You get syntax-highlighted code blocks, Vue components, interactive demos, and export to PDF or a web URL. More importantly, your slides live in a Git repo — which means version history, pull requests, and the same review workflow you use for code. For a technical talk where the content evolves over time, that's actually a meaningful advantage.

**Zod** solves a TypeScript problem that trips up a lot of developers. TypeScript types are compile-time only — they get erased when your code runs. So when data arrives from an external API, your type annotations are essentially a promise you're making to yourself, not a guarantee. Zod lets you define a schema that validates data at runtime. If the shape doesn't match — wrong type, missing field, invalid email format — it throws with a clear, descriptive error. It pairs especially well with tRPC, where you can share the same schema between your front-end and back-end and get end-to-end type safety that actually holds up at runtime.

**Playwright** is the answer to "what do I use for end-to-end browser testing in the current decade." Selenium is twenty years old, and it shows. Playwright is Microsoft's 2020 replacement — supports Chromium, Firefox, and WebKit, handles async behavior automatically so you're not littering your tests with manual wait calls, and includes a code generator that watches you click through your app and writes the test for you. That last part alone saves a significant amount of boilerplate.

And finally, **Mermaid**. If you've ever written architecture documentation that went stale because the diagram lived in a separate tool, Mermaid is the fix. You write a simple text-based syntax — describe nodes, connections, sequence of events — and it renders as a flowchart, sequence diagram, or Gantt chart. GitHub, GitLab, and Notion all render it natively. That means your architecture diagrams live in the same repo as your code, go through code review, and stay in sync with the implementation. That's what documentation should look like.

Three things to take away from all of this. First: the most useful tools are focused. Every one of these does one thing instead of trying to be a platform, and that's exactly why they're easy to evaluate and easy to adopt. Second: the "self-hostable alternative to X" category is genuinely worth paying attention to — Hoppscotch versus Postman is the obvious example, but the pattern applies broadly when ownership and data control matter to you. And third: act is probably the single highest return-on-investment install here if you're spending any meaningful time waiting on CI. Fixing that feedback loop pays dividends immediately.
