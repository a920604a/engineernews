你的 GitHub stars 裡有多少 repo 是「加星之後再也沒打開過」的？今天介紹的這十個，不一樣——它們各自解決一個非常具體的痛點，很多裝上去三天內就會用到。

先說 Carbon。你在寫技術部落格或做分享的時候，有沒有遇過截圖出來的程式碼看起來超醜這個問題？Carbon 就是專門解決這件事的。你把程式碼貼進去，選主題、字型、背景，它幫你輸出一張乾淨好看的圖。唯一的限制是：圖片沒辦法複製貼上，所以如果你需要別人能直接用的程式碼，這不是對的工具。

第二個是 Excalidraw。Lucidchart 和 Draw.io 畫出來的圖太正式，有時候你只是需要一個快速草圖。Excalidraw 的特色是它生成的圖刻意做成手繪風格——不是因為做不到精緻，而是這種感覺反而更容易傳達「這是討論中的架構，不是定稿」。完全開源可以自架，支援即時協作，VS Code 裡面也有 extension 可以直接用。

第三個是 nektos/act，這個對於常寫 CI 的人來說大概是今天最有感的工具。每次改 workflow 都要 push 才能測，等 CI 跑完，錯了再改再 push——這個循環非常浪費時間。act 讓你在本機用 Docker 直接跑 GitHub Actions workflow。你可以執行整個 push event 的所有 workflow，也可以單獨跑某一個 job。要注意的是部分 GitHub 內建的 action 在本機跑需要額外設定，不是百分之百無縫，但迭代速度已經快很多了。

第四個是 Hoppscotch，定位是開源版的 Postman。Postman 免費版的功能越來越縮水，而且你的 API collection 是存在他們的雲端上的。Hoppscotch 支援 REST、GraphQL、WebSocket，可以完全自架，資料留在自己手上。如果你的公司有 API 安全政策，這個方向更合理。

第五個是 Bun 內建的 Shell。如果你用 JavaScript 或 TypeScript 寫構建腳本，以前的選項不是很好看——原生的 child process API 太囉嗦，第三方的 shell 套件又太老。Bun Shell 讓你直接在 TypeScript 裡面用很接近 shell 的語法執行系統指令、抓輸出、列出檔案，而且跨平台，在 Windows 上也能用，還有完整的型別支援。

第六個是 Ink，用 React 寫終端機 UI 的工具。你不需要學任何底層的終端機 API，用你熟悉的 React component 概念來寫——有 flexbox 佈局，有顏色控制，有狀態管理。Gatsby 和 Parcel 的 CLI 介面都是用 Ink 做的，所以這不是玩具，是有生產驗證的東西。

第七個是 Slidev，給工程師用 Markdown 寫投影片的工具。程式碼區塊有語法高亮，可以嵌入互動 demo，可以匯出 PDF 也可以部署成網頁。最有吸引力的一點是：投影片放進 Git 做版本控制，這對工程師來說比 PowerPoint 更自然。

第八個是 Zod，TypeScript 的執行時期型別驗證。TypeScript 的型別只存在於編譯階段，執行時期消失了。所以當你從 API 拿到資料，你沒辦法確定它的型別真的符合你的預期。Zod 讓你定義一個 schema，然後在執行時期用它去驗證資料——如果格式不符，會拋出清楚的錯誤訊息，而不是在程式深處莫名其妙爆炸。配合 tRPC 用效果特別好，可以前後端共享同一份 schema。

第九個是 Playwright，Microsoft 在 2020 年發布的 E2E 測試工具。對比 Selenium——Selenium 的設計是 2004 年的東西，API 用起來很不直覺，而且要自己處理很多等待邏輯。Playwright 支援三個主流瀏覽器引擎，有自動等待機制，不需要手動寫 sleep，還有一個 codegen 功能，可以錄製你的操作然後自動生成測試程式碼，入門門檻低很多。

最後是 Mermaid，在 Markdown 裡直接寫文字就能生成流程圖、序列圖、甘特圖。GitHub、Notion、GitLab 都原生支援它。最大的意義是：架構圖和程式碼在同一個 repo 裡，可以做 code review，可以用 git 追蹤修改歷史。這才是技術文件應該有的狀態。

總結三個今天帶走的觀念：第一，這些工具每一個都只解決一件事，定位清晰的工具反而最好評估值不值得用。第二，如果你在 CI 上浪費很多時間，act 是今天最該先試的；如果你有型別安全的需求，Zod 值得優先看。第三，Mermaid 和 Excalidraw 的組合，基本上可以讓你的技術文件完全活在 Git 裡面——這個改變比你想的更有價值。
