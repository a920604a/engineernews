1995 年，Brendan Eich 用 10 天創造了 JavaScript。這個故事大家都聽過。但接下來的十年，這個語言基本上被嚴肅的工程師當成笑話——能不碰就不碰。

改變這個局面的不是語言本身的升級，而是一個叫 Douglas Crockford 的人。

Crockford 是 Yahoo! 的 JavaScript 架構師，從 1980 年代就開始寫程式。他沒有創造 JavaScript，但他做了三件幾乎拯救這個語言的事。

第一件事，是 JSON。2001 年，Crockford 需要讓瀏覽器和伺服器互相傳遞資料。當時標準做法是 XML 加上 SOAP 這個組合，複雜到荒謬的程度。他注意到 JavaScript 的物件語法本身就是完美的資料格式——輕量、易讀、每個 JavaScript 環境都能直接解析，根本不需要額外的解析器。於是他申請了 json.org 這個網域，把這個格式完整規範化，然後推廣出去。2006 年，JSON 正式成為 IETF 的國際標準。今天你每天都在用它，不管是 API 回傳值、設定檔還是前後端溝通，幾乎無所不在。他沒有發明 JSON 的語法——那就是 JavaScript 本來就有的物件字面量——但他讓整個產業接受了它。

第二件事，是 JSLint。2002 年他釋出了這個靜態分析工具，用來掃描 JavaScript 程式碼，挑出潛在錯誤和不良寫法。他自己的描述是：「JSLint 會傷害你的感情。」因為它嚴到幾乎任何隨手寫的程式碼都會被它罵一頓。但這正是價值所在。在 JSLint 之前，JavaScript 的生態系是「能跑就好」的狀態，沒有靜態分析，沒有風格標準。JSLint 是第一個站出來說「JavaScript 也可以有品質標準」的工具。今天大家在用的 ESLint，精神上就是 JSLint 的繼承者。

第三件事，是 2008 年出版的《JavaScript: The Good Parts》。這本書只有 176 頁，但它改變了一整個世代工程師看待 JavaScript 的方式。核心論點是：JavaScript 裡面其實藏著一個設計良好的語言，只是被大量糟糕的設計決定包圍著。如果你選擇只用那些「好的部分」——原型繼承、閉包、函式式特性——你會發現這其實是個優雅的語言。在當時，這個觀點是真正的異端。大多數人的直覺是「這個語言整個都很爛」，而 Crockford 說：不，是你用錯了。

這就是 Crockford 和 Eich 貢獻性質上的差別。Eich 創造了語言本身，而 Crockford 在語言最低谷的那十年，用工具和論述重新定義了什麼叫做「好的 JavaScript」，為後來 Node.js、npm 整個生態系的爆發打好了文化基礎。

收尾來講三個核心點。第一，JSON 不是被發明的，是被正式化的——Crockford 的貢獻在於整理和推廣，而不是憑空創造。第二，一個語言能不能被嚴肅對待，工具和論述的影響力不亞於語言本身的設計。第三，有時候技術的成功，靠的是有人願意花時間說清楚「它值得被認真對待」，然後用作品去說服其他人。Crockford 就是那個人。
