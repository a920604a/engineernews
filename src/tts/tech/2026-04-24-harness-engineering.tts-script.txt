各大公司不斷推出新的語言模型，但今天這個故事的主軸其實是：有時候語言模型不是不夠聰明，它只是缺乏人類的引導。

幾天前 Google 推出了開源的 Gemma 第四代，除了號稱很強，它還有一些特別小的版本，比方說 Gemma 4 2B。名字裡的 2B，代表它只有 20 億個參數，是個非常小的模型，號稱連 Edge 端、也就是你自己的機器上都跑得動。既然開源，那就下載下來玩玩看。

那麼問題來了：這麼小的模型，能不能拿來驅動一個 AI Agent？

我做了個小實驗。任務很單純：資料夾裡有一個 parser.py，裡面有個函式叫 extract_email，作用是從一段文字裡把 email 擷取出來，但當初寫的時候有 bug，不是所有 email 都抓得到。我要模型去修好它，最終讓另一個測試檔 verify.py 完全通過。這兩個檔案，就跟語言模型放在同一個資料夾裡。

但語言模型本身不會自動變成 Agent，你得給它工具。這裡我用一個很簡單的約定：模型如果輸出一段被標記成 bash 的指令，環境就自動幫它執行；如果輸出一段被標記成 python 的程式碼，環境就幫它存成檔案、跑起來。於是模型手上就有了三種能力：下 bash 指令、寫 python、執行 python。

第一次嘗試，Gemma 4 2B 讀完指令後，第一個反應竟然是：「沒有 parser.py 啊。」

為什麼？因為對模型來說，它的 context 裡只有「parser.py 這個檔名」這串文字，並沒有檔案的內容。就算檔案真的躺在旁邊，模型也不會自動知道，它只看得到你輸入的文字。於是它自作主張，根據題目提到的 extract_email，憑空幻想出一個 parser.py 應該長什麼樣子，寫了一段自己想像的程式碼，接著幻想自己驗證過了，然後宣稱完成。

這當然不是我們要的。但你仔細想想，這其實不是一個笨模型，它完全知道 parser.py 裡該有什麼，也有能力寫出正確的 email parser，它只是沒想到那個檔案就在它腳邊。模型的想法常常跟人不一樣，你直覺覺得出題就該附上程式碼，但它沒料到相關檔案就在腳下。

第二次嘗試，我只多打了幾行字，不到八十個字，而且不是針對這個特定任務的提示，而是一些通用原則。第一，你身處一個 Linux 環境。第二，做任何事之前，先看看你所在的資料夾裡有什麼。第三，要改一個檔案之前，別直接改，先打開它看看內容。第四，定義什麼叫「完成」，要達成既定標準才算數。

同一個 Gemma 4 2B，只加了這段原則，行為就完全不同了。它先 ls 列出目錄，發現有 parser.py 跟 verify.py；接著把 parser.py 的內容印出來、讀進 context；有了真正的內容之後，它整份重寫、覆蓋掉原檔；最後執行 verify.py 自我驗證，看到成功，結束任務。這就接近我們要的結果了。同一個模型，多加幾行指令，能力可能天差地遠。

那麼當你的 AI Agent 表現不如意時，到底該改哪裡？先回想 AI Agent 是由什麼組成的。它其實有兩部分：一是它呼叫的大型語言模型，可以是 Claude、Gemini、GPT，可以在雲端也可以在地端；二是一大堆支撐它去呼叫模型、操控工具的程式框架。這個模型輸出、驅動工具、再把結果餵回去的循環，就靠這層框架撐起來。

過去這「其他的東西」沒有好名字，現在有了共同的名字，叫 Harness，也就是馬具。很多人把它意譯成「駕馭」，於是打造 Harness 這件事，就叫 Harness Engineering，駕馭工程。象徵的意涵是：AI 是一匹力量強大的馬，要駕馭它，你需要馬鞍、韁繩，這些就是 Harness。

所以要強化一個 AI Agent，有兩條路：一條是改語言模型，自己訓練或微調一個更好的；另一條是改 Harness，打造更好的馬具。而 Harness 這條路，現在超級熱門，Anthropic、OpenAI 這一年來陸續發了好幾篇談 Harness 的文章。

這個詞真的很實際。舉個例子，Claude 的訂閱用戶曾收到通知，說訂閱帳號不再支援第三方 Harness，像是 OpenClaw。背後原因跟付費模式有關。用大型語言模型有兩種付法：一種是按 Token 用多少付多少；另一種是訂閱制吃到飽，付月費後理論上可以無限次呼叫。過去服務商覺得月費制沒問題，你是個人類，能輸入多少指令？但 OpenClaw 這類工具有心跳機制，可以每隔幾分鐘就自動送一次指令，服務商就吃不消了。於是 Claude 決定，這類 Harness 以後不能再接它的模型。換句話說，OpenClaw 現在被普遍認知為「一種 Harness」。

這裡也順帶講一個詞的演進。當人們想認真對待一件事，就會在後面加上 engineering。所以先有 Prompt Engineering，後有 Context Engineering，現在有 Harness Engineering。三者高度重疊，但強調的核心不同。

Prompt Engineering 講的是，語言模型在做文字接龍，輸入不同、接出來就不同。過去模型較弱，同一個問題換個問法，答案可能天差地遠，於是有人研究怎麼下 prompt，最知名的咒語就是「think step by step」。但這類咒語會越來越沒用，現在的模型你不強調，它也會認真思考，有沒有咒語差別越來越小。

Context Engineering 則是，咒語失效後，人們發現模型答錯往往不是能力不行，而是接龍時沒有足夠的資訊。於是需要一個系統去找到合適的 context、組成 prompt 再丟給模型。你可以說，它是一種更有系統、更自動化的 Prompt Engineering。

Harness Engineering 強調的則是「把任務完成」。今天模型解任務不再是一問一答，而是多輪互動：人類給任務、模型產生輸出、輸出驅動工具、模型看到結果，循環直到得出答案。怎麼駕馭這整個過程，就是它要處理的事。它跟 Context Engineering 的邊界其實有點模糊，但它想傳達的價值就是：讓模型能在多輪對話中把事情做好。

那人類到底能用哪些手段來駕馭模型？我舉三個例子。

第一種，控制認知框架。你可以用人類語言寫成的規則去影響模型，這些規則就像人類社會的法律。做法是讓模型在做任何事之前，都先把這些規則放進 prompt。這類規則往往有固定檔名，比方說 agents.md，你可以把它想成「給語言模型的 README」。模型怎麼知道要先讀它？這是 Harness 裡寫死的規則，模型一啟動就強制先讀某些檔案，確保它們進到 prompt，再做別的事。

當然，自然語言寫的規則沒辦法百分之百控制行為，模型要不要遵守其實看它自己，就像法律擺在那，也不是每個人都守。所以有人認為沒強制力就不算 Harness，但也有人把這種方式叫作 Natural Language Harness，它是一種用自然語言當馬具的 Harness。以 OpenClaw 為例，它每次對話開始前，都會先打開 workspace 裡的 agents.md，確保內容進入 prompt。模型因此知道自己的靈魂在哪、記憶存在哪、要找更久以前的記憶該去哪裡搜。

那 Claude 不讓 OpenClaw 呼叫了怎麼辦？其實很簡單。Anthropic 有自己的官方 Harness，像 Cowork、Claude Code，它們預設每次啟動會先讀 workspace 下的 CLAUDE.md。也就是說，Cowork 的 CLAUDE.md 大致等於 OpenClaw 的 agents.md。要把一個 Agent 從 OpenClaw 搬到 Cowork，你唯一要做的，就是把 agents.md 改名成 CLAUDE.md，Agent 就「復活」了。它甚至還會主動說，這份設定裡有些工具我其實沒有，要不要幫你改一下。只要你懂背後原理，搬家真的是舉手之勞。

那 agents.md 到底有沒有用？過去大家憑直覺亂寫，沒什麼系統研究，今年開始有 paper 認真研究了。今年一月一篇 paper 去 GitHub 上找大量含 agents.md 的 repo，比較有跟沒有的差別，結果顯示它能加快運作、用更少 token、更短時間完成任務，尤其對那些本來要花超久的 edge case 幫助比較明顯。不過這篇只量了速度，沒量做得對不對。二月另一篇就直接量正確率，它比較三種情況：沒有 agents.md、模型自己寫的、還有人類寫的。結果很有意思：人類寫的並不總是有用，在一些較強的模型上甚至沒發揮作用；而模型自己寫的更慘，多數時候比人類差，甚至比完全沒有還糟。

這告訴我們，人類目前可能還沒真的很會操控語言模型。另外 OpenAI 也提醒，agents.md 不能太長。他們試過把模型該知道的一切全塞進去，做成一本六法全書，結果表現非常差，光那本大書就佔掉大部分 context，根本沒空間做別的。他們強調，agents.md 應該像一張地圖，主要告訴模型「想知道某件事該去哪裡找」，而不是把所有內容都塞進去。

第二種手段，控制能力邊界，也就是限制工具。就算把 agents.md 改名成 CLAUDE.md，OpenClaw 跟 Cowork 因為背後可用的工具不同，行為還是差很多。OpenClaw 跑在你的電腦上，想看什麼就看什麼，可以任意改你的檔案，甚至有操控瀏覽器的工具，理論上可以幫你上傳影片、當個 YouTuber。Cowork 則是雲端沙盒，不跑在你電腦上，它要看你電腦的東西，得由你選擇掛載資料夾，而且每次掛載都要人類同意。這裡有個關鍵：那個「是否同意掛載」的確認視窗，不是模型要問的，而是背後 Harness 寫死的一行程式。就算你叫 Agent 別再問，它照樣會跳，因為那不是模型能決定的。所以 Cowork 相對安全很多。但安全跟方便是一個 trade-off，安全性高、便利性就低，反之亦然。

第三種手段，控制行為，也就是制定工作流程，讓模型嚴格遵守。

好，來收個尾。給你留三個重點。

第一，一個 AI Agent 等於語言模型加 Harness。當它表現不如預期，除了換更強或微調過的模型，打造更好的 Harness，往往同樣關鍵。

第二，駕馭模型有三種常見手段：用自然語言規則控制認知框架、用工具限制控制能力邊界、用工作流程控制行為。而像 agents.md 這種自然語言規則，別寫太長，把它當成一張地圖，而不是六法全書。

第三，回到那個小實驗，同一個 Gemma 4 2B，加上幾行通用原則，就從「幻想檔案」變成「會探索、會驗證」。模型不是不夠聰明，它有時候，只是缺乏人類好好的引導。
