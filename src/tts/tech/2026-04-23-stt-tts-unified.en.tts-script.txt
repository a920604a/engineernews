STT-TTS Unified 是一個自架平台，它把「語音合成」跟「語音辨識」——也就是 TTS 跟 STT——收攏進同一個網頁介面裡。它的設計方向非常清楚：語音合成這邊，直接借用微軟 Edge TTS 的免費神經網路語音；語音辨識這邊，則是把 OpenAI 的 Whisper 完全跑在本機的 CPU 上。整套系統，不需要顯示卡，也不需要任何一把 API 金鑰。

先講講，為什麼要這樣設計。

通常你要同時做語音合成跟辨識，得把好幾個工具東拼西湊起來；而商業 API 又常常伴隨著用量計費跟金鑰管理的麻煩。這個專案把兩件事折進單一介面，而且刻意把成本壓到零。TTS 這邊，直接呼叫微軟免費的語音服務，提供三百二十二種多語言語音，還會根據你輸入的語言，自動幫你過濾出可用的聲音。STT 這邊，用的是開源的 Whisper 模型，完全在本機跑，可以離線運作。

它的取捨切得很乾淨：TTS 需要連網，因為要打微軟的服務；STT 則是完全本地、能離線。而兩邊，都不需要金鑰。

再來，這套東西是純 CPU 就能跑的，不用顯示卡。它對硬體的要求很低：CPU 隨便一顆現代處理器就行，多核心當然更好；記憶體最低四 GB，但如果你要跑中型或大型模型，建議八 GB 以上;硬碟大概留五到十 GB，把 Docker image 也算進去；至於 GPU，完全不需要。

Whisper 預設用的是 base 模型，在一台普通筆電的 CPU 上，辨識一段語音大概要十到三十秒。如果你想要更高的準確度，可以在設定檔裡切換到 small 或 medium，完全不用升級硬體。

接下來聊架構，這是我覺得最值得說的部分。

後端設計裡最巧妙的一手，是它用「Protocol 介面加上工廠函式」的方式，把 STT 跟 TTS 引擎抽象化了。它先定義兩個 Protocol，一個叫 STTEngine、一個叫 TTSEngine；然後 WhisperEngine 跟 EdgeTTSEngine 各自去實作對應的介面；最後由一個工廠函式，根據設定回傳真正要用的引擎。

這代表什麼？意思是說，未來你如果想把 Whisper 或 Edge TTS 換掉，只要新增一個實作了對應 Protocol 的新類別就好，所有呼叫它的地方，一行都不用改。這就是把引擎變成可抽換零件的威力。

整個資料流大概是這樣走的：使用者操作前端，前端是 React 19 加 Vite 加 TypeScript 蓋出來的介面，透過 REST API 打到後端的 FastAPI；FastAPI 再經過剛剛講的工廠函式，決定要拿 EdgeTTSEngine 還是 WhisperEngine；TTS 那條路會透過 edge-tts 連出去打微軟；STT 那條則是在本地跑 Whisper；而所有的結果，都會寫進一個 SQLite 資料庫裡。前端的 UI 用了蘋果人機介面指南的語意化配色，還支援會自動跟隨系統的深色模式。所有合成跟辨識的結果都存進 SQLite，所以你可以從歷史紀錄裡，回頭播放跟下載音檔。

這裡有個細節值得單獨拉出來講，就是 STT 的非阻塞流程。

語音辨識是很耗時的工作，所以它採用了背景轉錄的做法。當你上傳一個音檔之後，Whisper 的推論會在背景默默進行，即時的進度會透過 SSE、也就是 Server-Sent Events 推送給你，完成之後還會跳一個瀏覽器通知提醒你。這樣的好處是，使用者不用死盯著螢幕乾等，其他操作也不會被卡住。

對照一下兩邊的流程：TTS 這條，是你輸入文字，系統自動偵測語言、過濾可用語音，然後打 edge-tts 到微軟，生成音檔、寫進 SQLite，最後就能播放跟下載。STT 那條，是你上傳音檔，Whisper 在背景推論，過程透過 SSE 推即時進度，完成後跳瀏覽器通知，寫進 SQLite，最後把辨識出來的文字顯示出來。

至於設定跟部署，它把所有組態集中在根目錄的一個 config.yaml 裡，用階層式的結構，讓你可以分開調 STT 引擎——像是模型、裝置、語言——跟 TTS 引擎——像是預設語音、重試次數。

這些設定還能被環境變數覆寫，優先順序是環境變數大於 .env 檔、再大於 config.yaml。命名規則是用「區段、雙底線、子區段、雙底線、鍵」的格式，後端則是透過 Pydantic 的巢狀設定，統一去讀取這整套階層。

部署上，它用 Docker Compose 的多階段建置，做到一行指令就能啟動。你只要 clone 下來、進資料夾、下一個 make up，服務就跑在 localhost 的 8008 埠上了。如果你要做本地開發，也有對應的指令，可以一次把後端跟前端同時拉起來。

那,總結一下。

第一，這個專案最核心的價值，是用一個非常務實的組合——TTS 借微軟的免費語音、STT 用本地 Whisper 跑純 CPU——把語音合成跟辨識，收進同一個自架介面，而且做到全程零成本、免顯卡、免金鑰。

第二，架構上最漂亮的一筆，是 Protocol 加工廠模式，把引擎變成可以隨時抽換的零件，未來要換底層模型，呼叫端完全不用動。

第三，體驗上它把耗時的辨識做成背景任務，配上 SSE 即時進度跟瀏覽器通知，讓你不用乾等。

說到底，它就是一個給想自架語音工具、又不想付雲端費用的人，一個輕量又乾淨的起點。
