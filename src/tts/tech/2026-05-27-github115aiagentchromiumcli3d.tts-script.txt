這週的 GitHub trending 頁面，我一口氣找到五個讓人眼睛發亮的專案，四個不同的技術方向——AI 代理人、隱私瀏覽、CLI 自動化、還有 3D 重建——而且每一個都有實質的程式碼可以立刻動手試。

先從最有野心的開始說。

第一個是桌面 AI 代理人框架。概念很直接：讓 LLM 直接看著你的螢幕截圖，然後決定要點哪裡、打什麼字——就像一個遠端操作你電腦的人，只不過那個「人」是 GPT-4o 或 Claude。

這個思路的有趣之處在於，市面上大部分 AI 代理人框架都預設你要整合的軟體有 API。但現實是，有大量的遺留系統根本沒有 API——三十年前的企業軟體、政府系統。這個框架的答案是：沒有 API？那就讓 AI 像真人一樣用眼睛看、用手操作。可靠性目前還不到生產環境水準，但當 PoC 工具或自動化測試已經很夠用了。

第二個是一個 Chromium 分支，把 Google 塞在瀏覽器裡的所有遙測和後台呼叫全部砍掉。

這件事聽起來簡單，但 Chromium 原始碼裡的 Google 服務呼叫其實非常密集：自動更新、Safe Browsing 資料同步、用量統計回報、功能旗幟的遠端控制……這個專案的價值不只是「更隱私」，而是**透明性**——每一個改動都有詳細說明，讓你知道原本的瀏覽器在做什麼。對政府機關、金融業、醫療院所這種對資料洩漏有嚴格要求的組織，這種可審計性本身就是需求。

第三個是個 Python 框架，用一個裝飾器就能把任何函式變成完整功能的 CLI 工具，自動幫你生成說明文件、參數解析、甚至 tab 補全。

你在函式的型別標注裡寫好參數，加上一個裝飾器，這個框架就自動生成對應的命令列界面——包括 `--help` 說明，預設值都幫你填好。

這解決了一個非常真實的問題：大量的 ML 腳本和資料處理工具都停留在「只有原作者知道怎麼用」的狀態，因為沒有人想花額外的時間寫 argparse。這個框架把 CLI 界面的建置成本壓到幾乎為零。

第四個是一個為程式碼庫建立知識圖譜的工具，專門給 AI coding agent 用。

它分析你的程式碼庫，建立函式、類別、模組之間的呼叫關係圖，同時加上語意向量索引。這樣一來，AI 能夠回答「哪個函式負責處理 user authentication？」，而不是要把整個 codebase 全部塞進 context window 再搜尋。對超過百萬行的大型專案，這種結構化索引可以大幅減少 context window 的浪費，agent 的回答品質也會提升很多。

第五個是本週最讓我驚喜的：從單張照片即時生成可互動 3D 模型，而且快到可以在瀏覽器裡即時預覽。

基於 Gaussian Splatting 的優化版本，在消費級 GPU 上大概五到十秒就能從一張照片生成可以自由旋轉的 3D 場景。品質不如離線跑幾個小時的傳統 NeRF，但速度快了整整一個數量級。電商產品 3D 化、建築快速原型、遊戲資產生成——這個速度讓很多場景第一次變得可行。

回頭看這五個專案，有一個共同脈絡：它們都在把原本需要大量配置和專業知識的能力，壓縮成幾分鐘就能上手的工具。不需要 API 就能自動化 GUI、一行裝飾器就有 CLI 界面、不用等一夜就能拿到 3D 模型。

這是工具民主化的方向，而這週 GitHub 上跑得最快的，就是這類東西。
