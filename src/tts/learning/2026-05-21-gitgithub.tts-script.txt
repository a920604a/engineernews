你有沒有過這種經驗？電腦桌面上躺著一堆檔案，叫做 `final.docx`、`final_v2.docx`、`final_真的最終版.docx`……然後你自己都忘了哪個才是真正最新的。Git 就是來解決這個問題的。

Git 是一個版本控制工具，每一次你「提交」，就等於替你的專案拍了一張時間點的快照。你可以隨時回到任何一個歷史版本，看看當初改了什麼、為什麼改。和別人合作時，也不會發生「你的修改把我的蓋掉了」這種悲劇。GitHub 則是把這些 Git 專案放到雲端的平台，讓你可以從任何地方存取，也可以和其他人一起協作。

---

開始之前，你需要三樣東西：在 git-scm.com 下載 Git、到 GitHub 建立一個帳號、然後打開你的終端機。安裝完之後，在終端機輸入 `git --version`，看到版本號就表示一切就緒。

在動手之前，先把 Git 裡最重要的概念搞清楚。Git 把你的工作分成三個區域：

第一個是「工作目錄」，就是你電腦上實際在編輯檔案的地方，最直觀。

第二個是「暫存區」，你可以把它想成一個購物車——你決定這次要提交哪些修改，就先把那些檔案放進購物車裡。這個動作叫做 `git add`。

第三個是「本地倉庫」，就是正式的歷史紀錄檔。你執行 `git commit`，就是把購物車裡的東西結帳、永久記錄下來。

搞懂這三個區域，你再回頭看 Git 的指令，很多就會豁然開朗。

---

好，來實際操作。先到 GitHub 建立一個新的 repository，然後在你電腦上建一個資料夾，進去之後執行 `git init`，再用 `git remote add origin` 加上你的 GitHub 網址，把這個資料夾和遠端的 repository 連起來。

接著是你以後每天都會重複的動作：改完東西之後，先 `git add` 把要提交的檔案放進暫存區，然後 `git commit` 加上一段說明文字，記錄這次改了什麼，最後 `git push` 推到 GitHub。就這三個步驟，add、commit、push，掌握這個循環，你的日常使用九成都夠用了。

第一次推的時候要多加一個參數，告訴 Git「這個分支預設推到 GitHub 的 main」，設定好之後，之後就只需要一個簡單的 `git push`。

---

講到 Git 最強大的地方，絕對是「分支」。你可以把分支想成平行宇宙——你在新的分支上做實驗、改東西，完全不影響主線。確定沒問題之後，再把它合併回來，主線永遠是穩定的版本。

實際操作上，你用 `git checkout -b` 加上你想要的分支名稱，比如說 `feature/add-login`，就建立了一個新的分支，同時切換過去。在這裡做你想做的修改、提交，確認沒問題之後，切回主分支，執行 `git merge` 把這個分支合併進來，再把那個分支刪掉。乾淨俐落。

不過有時候，兩個分支都動到同一個檔案的同一行，Git 就不知道該保留哪個版本，會跟你說「衝突了，你自己決定」。這時候打開那個檔案，你會看到一堆特殊符號把兩個版本都標示出來，你手動留下你想要的那段內容，把那些符號刪掉，再重新 add 和 commit，衝突就解決了。聽起來嚇人，其實做一次就習慣了。

---

幾個常用的查看指令也很值得記：`git status` 讓你看目前哪些檔案有改動，`git log --oneline` 用一行一行的方式列出提交歷史，非常清爽。

至於常見的問題，推送時出現權限錯誤，通常是身份認證的問題，GitHub 現在建議用 Personal Access Token，到帳號設定頁面產生一組，當密碼用就好。如果提交訊息寫錯了，還沒推出去的話可以用 `git commit --amend` 修正；但如果已經推到 GitHub 了，就不建議改了，因為會弄亂其他協作者的歷史紀錄。至於那些不想被 Git 追蹤的檔案，像是 `node_modules` 或是環境變數檔案，就寫進 `.gitignore` 裡，GitHub 有提供各語言的範本，直接用就好。

---

好，來總結一下今天最重要的三件事。

第一，Git 把你的工作分成工作目錄、暫存區、本地倉庫三個區域，搞懂這個架構，操作就不會再感覺像黑魔法。

第二，add、commit、push 這個循環是你的日常主力，掌握它，版本控制就上手了一大半。

第三，分支是 Git 的超能力——用它來做實驗、開發新功能，主線永遠保持乾淨穩定。

版本控制這件事，剛開始確實會有點不習慣，但用幾次之後你就會發現，回不去了。
