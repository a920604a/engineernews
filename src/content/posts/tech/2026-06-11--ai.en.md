Most people use AI by opening a chat interface, pasting a question, and looking at the output. That's "using AI."

Using AI well looks more like "collaborating with a knowledgeable colleague who needs explicit direction"—you provide context, you verify output, you know which tasks to delegate and which to keep.

Here are five concrete upgrades.

## TL;DR

1. **Context quality determines output quality**: vague input, vague output—more context doubles answer quality
2. **Multi-turn beats single-turn**: break complex tasks into steps, correct as you go, don't try to write the perfect prompt
3. **Know when AI is wrong**: factual recall is highest-risk, reasoning is relatively reliable
4. **Integrate into your workflow**: the chat box is the tip of the iceberg; real leverage is in the pipeline
5. **Only delegate what you can verify**: AI works best when you can evaluate the output

---

## 1. Context Quality Determines Output Quality

LLMs predict the next token based on what you gave them. Better context → more relevant output. Every vague prompt is a missed opportunity.

**Weak prompt:**
```
Write a login function
```

**Strong prompt:**
```
I'm using Next.js 14 + Supabase. I need an email/password login feature.
Supabase client is already configured at lib/supabase.ts.
I need: login form component, server action for login logic, error message display.
Not needed: OAuth, email verification (handled separately).
```

The second prompt provides stack, existing structure, scope, and exclusions. The output will fit your codebase rather than generating a generic template you'd have to adapt anyway.

**Role-setting technique:**
```
You are a Rust backend engineer reviewing the following code.
Focus on ownership issues and unnecessary clones.
```

Role-setting at the start of a prompt consistently improves output quality.

---

## 2. Multi-Turn Beats Single-Turn on Complex Tasks

Many people treat AI as a "produce one complete answer" tool. For complex tasks, iterative conversation consistently outperforms trying to write one perfect prompt.

**Why:** AI generating large amounts of output at once tends to lose focus. Multi-turn lets you catch errors early and correct direction without starting over.

**Pattern:**
- Round 1: Clarify understanding ("Tell me your approach first—don't write code yet")
- Round 2: Execute one concrete step
- Round 3: Review, identify problems, ask for fixes
- Repeat

Think of it as pair programming with an engineer who needs explicit direction, not a code generator you give one long spec.

## 3. Know When AI Will Be Wrong

This is the biggest gap between misuse and effective use.

**High risk:**
- **Factual recall**: "What version is this library at?", "What's the exact parameter name for this API?"—AI's training data has a cutoff and will confidently state outdated information
- **Arithmetic**: AI looks like it's calculating; it's actually predicting what the answer to this type of question usually looks like—not the same thing
- **Recent events**: anything after the model's knowledge cutoff

**Relatively reliable:**
- **Reasoning and analysis**: "Explain what this code does", "Compare these two architecture tradeoffs"
- **Generation tasks**: "Refactor this into a cleaner version"
- **Questions within a known framework**: "How do server actions work in Next.js?" (but verify against current docs)

**Rule of thumb:** Any specific fact AI states (URL, version number, function name, benchmark figure)—verify against the primary source before acting on it.

---

## 4. Integrate AI Into Your Workflow, Not Just Your Chat Tab

The biggest leverage isn't in the chat interface—it's in the pipeline.

**Typical engineer integrations:**

**Pre-commit code review:**
```bash
git diff --staged | claude "Review this diff: focus on security issues and obvious bugs"
```

**Documentation generation:**
```bash
cat src/api/routes.ts | llm "Generate OpenAPI 3.0 documentation for these routes"
```

**Test generation in Claude Code / Cursor:**
Mark a function, ask "write unit tests for this including edge cases," review, add to test suite.

**Tool comparison:**

| Tool | Best For | Weakness |
|------|---------|---------|
| Claude Code | Complex multi-step tasks, large codebase understanding | Needs substantial context each time |
| Cursor | Fast autocomplete, small edits | Tends to go off track on complex tasks |
| GitHub Copilot | Inline suggestions, IDE integration | Not suited for large refactors requiring judgment |

---

## 5. Only Delegate What You Can Verify

This is the most important and most ignored principle.

**Anti-pattern:** Let AI write a module you don't understand, merge it directly.

The problem isn't that AI-generated code is necessarily bad—sometimes it's excellent. The problem is **you have no way to evaluate whether it's correct**, which dramatically increases the probability of bugs reaching production.

**Using AI well looks like:**
- Reading and understanding every line of AI-generated code before it ships
- AI assists with analysis; you make the final judgment call
- AI-generated text: you can verify the factual claims

AI works best for "helping capable people go faster," not "helping people bypass a capability requirement."

## The Difference in Practice

| Behavior | Using AI | Using AI Well |
|----------|---------|--------------|
| Prompt quality | One or two sentences | Context, constraints, expected format |
| Verification habits | Use output directly | Check factual claims against sources |
| Integration depth | Chat interface only | Connected to git, IDE, CI pipeline |
| Task scope | Delegate everything | Only tasks you can evaluate |
| Iteration | One shot | Multi-turn, correct as you go |
