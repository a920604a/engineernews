# rewrite-crawl-drafts skill

爬蟲（`scripts/crawl.ts`）使用 `llama-3.1-70b-instruct` 自動生成文章，品質有限：大陸用語、捏造數據、空表格、Mermaid 語法錯誤。本 skill 用較強的模型（Claude Sonnet/Opus）全面重寫，讓文章達到發佈標準。

## 觸發時機

- 爬蟲跑完後積累了多篇 `draft: true` 草稿需要升品質
- 文章內容明顯是樣板、泛泛而談、或捏造了數據
- 需要批次讓草稿升格為可發佈狀態

## 品質問題清單（爬蟲常見）

| 問題 | 說明 |
|------|------|
| 大陸用語 | 代碼/芯片/存儲/內存/項目/組件/高质量 |
| 台灣用語 | 程式碼/晶片/儲存/記憶體/專案/元件/高品質 |
| 空白表格 | comparison 類型常見，只有 header 沒有數據 |
| 捏造數據 | 「生產效率提高30%」這類無來源的數字 |
| Mermaid 錯誤 | `-->|label|>` 應為 `-->|label|` |
| 錯誤理解主題 | 把 Cursor（AI 編輯器）寫成「通用框架」、把 Codex CLI 寫成手機 App |
| 參考資料造假 | 引用不存在的網址或維基百科條目 |

## 執行步驟

### Step 1：找出所有 draft 文章

```bash
grep -rl "draft: true" src/content/posts/ | grep -v '\.en\.md' | sort
```

### Step 2：對每篇文章執行重寫流程

針對每個 zh-TW draft 文章（及其對應 .en.md）：

**2a. 讀取原始草稿**
- 取得 frontmatter：title、original_url、type、date、category、tags

**2b. 查找真實內容**
- 若有 `original_url`（YouTube URL）：`WebSearch` 影片標題及主題關鍵字
- 也可嘗試 `WebFetch` YouTube 頁面取得影片描述
- 優先搜中文（台灣頻道）或英文（英文頻道）

**2c. 依 type 結構重寫**

| type | 結構 |
|------|------|
| `explainer` | [開頭] → TL;DR → 是什麼 → 為什麼重要 → 怎麼運作 → 跟X的差別 → 小結 → 參考資料 |
| `deep-dive` | [開頭] → TL;DR → 設計哲學 → 核心概念 → 跟常見替代方案比較 → 適合/不適合的情境 → 整體來說 → 參考資料 |
| `how-to` | TL;DR → 前置條件 → 步驟 → 完整範例 → 常見問題 → 參考資料 |
| `debug` | TL;DR → 情境 → 問題 → 嘗試過程 → 解法 → 為什麼會這樣 → 學到的事 → 參考資料 |
| `listicle` | TL;DR → 各項目（各有實質內容） → 總結 → 參考資料 |
| `comparison` | TL;DR → 比較對象 → 功能比較（實際數據表格） → 效能/成本 → 適用情境 → 結論 → 參考資料 |
| `research` | [開頭] → TL;DR → 研究背景 → 關鍵發現 → 影響與意義 → 限制與注意事項 → 參考資料 |
| `newsjacking` | TL;DR → 發生了什麼 → 為什麼值得關注 → 技術角度怎麼看 → 後續值得觀察的點 → 參考資料 |
| `case-study` | [開頭] → TL;DR → 背景與挑戰 → 解法設計 → 實作細節 → 成果 → 學到的事 → 參考資料 |

**2d. 字數目標**
- tech/product 類 zh-TW：1500–2500 字
- learning/career 類 zh-TW：1000–2000 字（偏散文風格）
- 英文版（.en.md）：zh-TW 的 60–80%

**2e. 寫入新檔案**

```bash
# 去掉檔名開頭的 _
# _2026-05-09-foo.md → 2026-05-09-foo.md（同目錄）
```

Frontmatter 必填格式（`draft: false` 必須明確寫出，不可省略）：

```yaml
---
title: "..."
date: [保留原始 ISO date]
category: [保留]
tags: ["tag1", "tag2"]
lang: zh-TW
tldr: "改善過的一行摘要"
description: "改善過的描述"
type: [保留原始]
original_url: "..."
draft: false
---
```

**2f. 刪除舊的 `_` 前綴檔案**

```bash
rm src/content/posts/<category>/_YYYY-MM-DD-slug.md
```

**2g. 處理對應 .en.md**

```bash
ls src/content/posts/<category>/_YYYY-MM-DD-slug.en.md
```

若存在：用相同流程重寫英文版，存為 `YYYY-MM-DD-slug.en.md`，刪除舊檔。

### Step 3：驗證結果

```bash
# 確認沒有剩餘 draft: true
grep -rl "draft: true" src/content/posts/

# 確認沒有殘留 _ 前綴檔案（正常爬蟲產出的草稿都應該被清理）
ls src/content/posts/**/_*.md
```

### Step 4：commit

```bash
git add src/content/posts/
git commit -m "refactor: rewrite crawler drafts with stronger model"
```

## 重寫品質規則

- **只用真實資訊**：參考資料只放確認存在的 URL；不發明數據
- **Mermaid 語法**：`A --> B` 或 `A -->|label| B`，禁用 `-->|label|>`
- **learning/career 類**：對話式散文風格，不濫用 Mermaid
- **tech 類**：工程師寫給工程師看，直接有觀點，不客套
- **沒有 original_url 的文章**：根據標題與現有內容推測主題，用一般知識重寫

## 規模建議

| 文章數 | 建議做法 |
|--------|----------|
| 1–5 篇 | 直接在主對話中逐一處理 |
| 6–20 篇 | 分 2–3 批，用 Agent 工具平行執行 |
| 20+ 篇 | 分 5 批（依 category/日期分），背景執行 5 個 Agent，主線程同時寫 skill 或其他任務 |

## 與 `post` skill 的差別

`post` skill 是從零開始寫新文章（從對話、筆記、GitHub 專案生成）。

`rewrite-crawl-drafts` skill 是改善已存在的爬蟲草稿：保留 frontmatter 結構，完整重寫內文，修正品質問題，讓文章從 draft:true 升格為 draft:false。
